# PMTiles Write-Path Profile Report

Recorded 2026-08-20.  Environment: macOS arm64, GDAL 3.12.2 (Homebrew),
Python 3.14.5, shapely 2.1.2, geopandas 1.1.4.

---

## Workload

Deterministic global point layer generated by `benchmarks/bench_write_pmtiles.py`
(seed = 42).  Each feature carries three properties: `id` (int64), `label`
(string), `value` (float64).  Default zoom range z0–8.

## Optimisation applied

Three changes to `_write_layer` in `src/geodataframe_to_pmtiles/_writer.py`:

1. **Batch WKB conversion** — replaced per-row `geom.wkt` +
   `ogr.CreateGeometryFromWkt` with a single `shapely.to_wkb(geom_arr[valid_idx])`
   call followed by `ogr.CreateGeometryFromWkb` in the loop.
   WKB preserves IEEE 754 double precision (more accurate than WKT text).

2. **Vectorised geometry filter** — replaced per-row
   `hasattr(geom, "is_empty") and geom.is_empty` with a single
   `shapely.is_missing(geom_arr) | shapely.is_empty(geom_arr)` mask before the
   loop, producing `valid_idx` as a numpy index array.

3. **Pre-normalised column lists** — replaced per-row `_normalise_value`
   (which called `pd.isna`, ran an `isinstance` chain, and converted numpy
   scalars) with per-column `Series.isna().tolist()` + `Series.tolist()` to
   build null flags and value lists before the loop.  `bool` columns are
   converted to 0/1 `int` upfront; `int`/`float` columns leverage numpy's
   own scalar conversion inside `tolist()`.  The `string` kind fast-paths
   plain `str` values and falls back to per-cell handling only for
   `datetime`, `list`/`dict`, and other non-str types.

**What is NOT changed:** public API, output semantics, feature order,
overflow checks, transactional output path, `_normalise_value` (still used
for the string-kind fallback), and all existing tests continue to pass.

## Comparison with private climate-monitor ERA5 run (scale context only)

The private climate-monitor workload is an ERA5 0.25-degree global grid
(approx. 1 M points, z0–8, 3 property columns).  These numbers are not
reproducible with the public benchmark; they are included for scale context
only.

| tool        | wall time | peak RSS  | archive  |
| ----------- | --------: | --------: | -------: |
| Tippecanoe  |   48.06 s |    690 MB |  73.5 MB |
| Library (pre-opt) | 77.36 s | 1.09 GB | 66.3 MB |

The compact benchmark workloads above are representative of the Python write
path but are much smaller than the ERA5 dataset.  The ERA5 gap (library
77 s vs Tippecanoe 48 s) is driven by GDAL's per-feature OGR API cost
(`Layer_CreateFeature`), which remains the irreducible bottleneck.  A
materialisation strategy using GDAL batch-write helpers or an alternative
vector-tile library would be needed to close that gap further.

---

## Remaining bottleneck

`Layer_CreateFeature` accounts for ~48% of total wall time at 5 k features
and grows linearly with feature count.  It is an OGR SWIG-layer C extension
call and cannot be batched via the current GDAL Python API.  Further
Python-level optimisations on the surrounding loop will have diminishing
returns.
